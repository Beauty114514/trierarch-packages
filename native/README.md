# Trierarch native

`trierarch-native` is the small, built-in PTY host used by Trierarch sessions.
It deliberately knows nothing about PRoot, root filesystems, display protocols,
configuration formats, or Android views.

Its only job is to start an absolute executable in a pseudoterminal, relay bytes,
resize the terminal, and reliably reap the child process.

## JNI contract

The future Android bridge is `app.trierarch.nativebridge.NativePtyBridge`.
Its Kotlin declarations must match these methods:

```kotlin
external fun openSession(
    command: String,
    arguments: Array<String>,
    workingDirectory: String,
    environment: Array<String>, // NAME=VALUE entries
    rows: Int,
    columns: Int,
    callback: SessionCallback,
): Long

external fun write(sessionId: Long, bytes: ByteArray): Boolean
external fun resize(sessionId: Long, rows: Int, columns: Int): Boolean
external fun close(sessionId: Long)

interface SessionCallback {
    fun onSessionOutput(sessionId: Long, bytes: ByteArray)
    fun onSessionExited(sessionId: Long, exitCode: Int)
}
```

`openSession()` returns `0` on failure. `write()` and `resize()` return `false`
for an unknown or closed session. Session identifiers are generated by native code;
the UI never supplies them.

The executable path must be absolute. The first argument is supplied separately:
native prepends `command` as `argv[0]`. For the initial shell profile, use
`/system/bin/sh` with `arguments = arrayOf("-i")`.

## Build

```bash
cargo test
cargo ndk -t arm64-v8a -P 24 build --release
```

The Android artifact is
`target/aarch64-linux-android/release/libtrierarch_native.so`. It is a build
artifact: the Android Gradle module will later copy/package it into the APK.
